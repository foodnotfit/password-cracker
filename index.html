🔬 Ages 15+ & Adults — Scientific References
🏛️ Official Standards — Password & Authentication Policy
NIST Special Publication 800-63B — Digital Identity Guidelines: Authentication & Lifecycle Management
NIST (2017, updated 2024)
The authoritative US government standard for password policies. Key guidance: minimum 8 characters (15 recommended), no mandatory complexity rules, no forced periodic rotation, check against breach corpuses, support passphrases up to 64+ characters. The basis for the strength rating system used in this demo.
NIST StandardPassword Policy
https://pages.nist.gov/800-63-3/sp800-63b.html
OWASP Password Storage Cheat Sheet
Open Web Application Security Project (2024)
Industry-standard guidance for secure password storage: first choice Argon2id, minimum bcrypt (work factor ≥10), never use MD5/SHA-1/SHA-256 directly without key stretching. Explains salting, peppering, and upgrade strategies. Basis for algorithm safety ratings in this demo.
OWASPBest Practice
https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html
🔐 Hash Function Science
MD5 Collision Attack — How It Was Broken
Wang, X. & Yu, H. (2005) — EUROCRYPT 2005, Springer LNCS 3494, pp. 19–35
Demonstrates practical MD5 collisions — two different inputs producing the same hash — in under one minute on 2005 hardware. This is why MD5 is marked "Broken" in this demo and must never be used for security-sensitive applications.
MD5 BrokenCollision
https://link.springer.com/chapter/10.1007/11426639_2
SHAttered — First Practical SHA-1 Collision
Stevens, M., Bursztein, E., Karpman, P., Albertini, A. & Markov, Y. (2017) — USENIX Security 2017
First practical SHA-1 collision — two PDF files with identical SHA-1 hashes, computed using ~6,500 CPU-years and 110 GPU-years of computation. Confirms SHA-1 deprecation status. The attack cost is now within reach of nation-state and well-funded adversaries.
SHA-1 Broken
https://shattered.io/
FIPS 180-4 — Secure Hash Standard (SHA-2 / SHA-256)
NIST (2015) — Federal Information Processing Standard 180-4
Official specification for the SHA-2 family. SHA-256 is cryptographically sound against collision attacks but its speed (~3 billion hashes/sec on a modern GPU) makes it unsuitable for direct password storage without key-stretching (bcrypt/Argon2). SHA-256 is appropriate for data integrity, digital signatures, and HMAC.
SHA-256NIST Standard
https://csrc.nist.gov/publications/detail/fips/180/4/final
FIPS 202 — SHA-3 Standard (Keccak Sponge Construction)
NIST (2015) — Federal Information Processing Standard 202
Official specification for SHA-3 using the Keccak sponge construction — a fundamentally different design from SHA-2, providing cryptographic diversity and quantum-safe properties. Selected as NIST's quantum-safe hash standard. Throughput: ~1 billion hashes/sec on modern hardware.
SHA-3Quantum Safe
https://csrc.nist.gov/publications/detail/fips/202/final
BLAKE3 — One Function, Fast Everywhere (Technical Specification)
O'Connor, J., Aumasson, J-P., Neves, S. & Wilcox-O'Hearn, Z. (2020) — BLAKE3 Team
BLAKE3 achieves higher throughput than MD5 while providing 256-bit security with a provably sound design. Highly parallelizable using AVX-512 SIMD. Quantum-safe: 256-bit output provides 128-bit post-quantum security via Grover resistance. No key stretching inherently — use Argon2 for passwords.
BLAKE3Quantum Safe
https://github.com/BLAKE3-team/BLAKE3-specs/blob/master/blake3.pdf
🛡️ Memory-Hard Password Hashing (bcrypt & Argon2)
A Future-Adaptable Password Scheme (bcrypt — Original Paper)
Provos, N. & Mazières, D. (1999) — USENIX Annual Technical Conference 1999
Introduces bcrypt with adaptive cost factor — deliberately slow to make brute-force attacks impractical regardless of hardware improvements. At work factor 12: ~100,000 hashes/sec vs ~3 billion/sec for SHA-256 on identical hardware — making attacks approximately 30,000× harder. Still the minimum acceptable standard for password storage today.
bcryptKey Stretching
https://www.usenix.org/legacy/events/usenix99/provos/provos.pdf
Argon2: Memory-Hard Function for Password Hashing — Password Hashing Competition Winner (2015)
Biryukov, A., Dinu, D. & Khovratovich, D. (2015/2016) — IEEE EuroS&P 2016
Argon2 won the Password Hashing Competition (2015) and is the current OWASP/NIST recommended algorithm for new systems. Three variants: Argon2i (side-channel resistant), Argon2d (GPU/ASIC resistant), Argon2id (both — recommended). Memory-hard design requires large RAM allocation, neutralizing GPU and ASIC parallelism. ~1,000 hashes/sec at recommended settings — 3 million× harder than SHA-256.
Argon2Memory HardBest Practice
https://www.password-hashing.net/argon2-specs.pdf
⚛️ Quantum Threats to Password Security
A Fast Quantum Mechanical Algorithm for Database Search (Grover's Algorithm)
Grover, L. K. (1996) — Proceedings 28th ACM STOC, pp. 212–219
Grover's algorithm provides O(√N) quantum speedup for brute-force search — halving the effective bit-security of hash functions on a quantum computer. A 256-bit hash provides only 128-bit security against a quantum adversary. Memory-hard functions (bcrypt/Argon2) require quantum RAM proportional to their memory usage, effectively neutralizing Grover speedup on near-term hardware — which is why they are marked quantum-safe in this demo.
Grover's AlgorithmQuantum Threat
https://arxiv.org/abs/quant-ph/9605043
NIST SP 800-131A Rev 2 — Transitioning the Use of Cryptographic Algorithms and Key Lengths
NIST (2019, revised 2022)
NIST guidance on quantum-era key length requirements. Recommends 256-bit symmetric keys for long-term quantum security (providing 128-bit effective post-Grover security). Defines the approved and deprecated algorithm lists that form the basis for the algorithm safety ratings shown in this demo.
Post-QuantumNIST
https://csrc.nist.gov/publications/detail/sp/800-131a/rev-2/final
NIST Post-Quantum Cryptography Standards — FIPS 203, 204, 205 (August 2024)
NIST Computer Security Resource Center (2024)
The three finalized post-quantum cryptography standards: FIPS 203 (ML-KEM/Kyber — key encapsulation), FIPS 204 (ML-DSA/Dilithium — digital signatures), FIPS 205 (SLH-DSA/SPHINCS+ — hash-based signatures). These replace RSA and ECC for asymmetric cryptography. Not directly for password hashing, but provide context for the quantum-safe badges in this demo.
PQC StandardsNIST 2024
https://csrc.nist.gov/projects/post-quantum-cryptography
📐 Cryptographic Foundations
Time-Memory Trade-Off in Cryptanalytic Attacks — Foundation of Precomputed Hash Lookups
Hellman, M. E. (1980) — IEEE Transactions on Information Theory, Vol. 26, No. 4, pp. 401–406
Martin Hellman's foundational paper on time-memory trade-off attacks — the mathematical basis for precomputed hash lookup tables (the "rainbow table" concept demonstrated in Phase 1 of this demo). Shows how storing precomputed hash chains allows cracking any password in a fixed set in near-constant time, trading storage for computation. Salting passwords defeats this attack entirely by making each hash unique.
TMTOCryptanalysis
https://ieeexplore.ieee.org/document/1056220
zxcvbn: Low-Budget Password Strength Estimation (Password Strength Measurement Science)
Wheeler, D. L. (2016) — USENIX Security Symposium 2016
The science behind realistic password strength estimation — models actual attacker behavior (dictionary attacks, pattern detection, keyboard walks, date patterns) rather than simplistic character class rules. The entropy and crack-time estimates in this demo follow this methodology: measuring how many guesses an intelligent attacker would need, not just counting character types.
Strength EstimationEntropy
https://www.usenix.org/conference/usenixsecurity16/technical-sessions/presentation/wheeler
